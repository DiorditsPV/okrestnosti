# Работа с серией плакатов

Этот файл описывает работу с репозиторием после клонирования.

- Один пользовательский запрос — одна папка `posters/<collection>/<request>/`. Все готовые изображения сохраняются в едином корневом `output/` без подпапок, с именем `<collection>--<request>--<poster-id>.png`. В папке запроса находятся `input/`, `prompt/`, `metadata/` и README со ссылками на результаты.
- В публичном `output/` сохранять одну финальную версию каждого сюжета. При замене переносить предыдущий результат и его запрос в локальный игнорируемый `archive/`; не удалять исходники, на которые ссылаются другие запросы. Флаг `latest` в `metadata/request.json` отмечает актуальные версии.
- Точный промпт сохранять в `prompt/<poster-id>.txt`, формулировку запроса — в `prompt/request.md`. Манифест запроса имеет `schema_version: 1`, относительные от папки запроса пути, SHA-256 входов, промпта и результата. Использовать существующий манифест как образец.
- Пользователя устраивает свободная художественная интерпретация. Поиск референсов, типографические подложки и отдельная подгонка кириллицы не обязательны. Сохранённые старые подложки — история процесса, а не требование к новым генерациям.
- Генерировать встроенным инструментом. Не переходить на отдельный API без просьбы пользователя. Один вызов на запрошенный сюжет; повторы — по запросу пользователя.
- Общая галерея находится в корне: `index.html`. После изменений запускать `python3 scripts/build_gallery.py`.
- `archive/legacy/` — локальная резервная копия до реорганизации. Не запускать оттуда старые упаковочные скрипты и не добавлять архив в публичный коммит.

## Генерация по фотографии пользователя

- Сначала просмотреть фотографию пользователя и 1–2 подходящих готовых плаката из корневого `output/`. Готовые плакаты являются визуальными референсами, а не просто примерами в документации.
- По умолчанию выбирать светлый Моссовет (`*02-mossovet-positive*`); для 1994–2000 — Водолей (`*03-vodoley-fix*`), для скейтерского 2007-го — Авангард (`*04-avangard-2007*`). Учитывать пожелания пользователя к стилю и сюжету.
- Передавать инструменту генерации сами изображения: фотографию как референс объекта и выбранные плакаты как референсы стиля. В промпте явно разделять эти роли; сохранять узнаваемость объекта с фото, заимствовать палитру, рисовку и позитивный тон плакатов, не переносить их здания и надписи.
- Для инструмента с `referenced_image_paths` использовать локальные пути всех выбранных изображений. Если фото доступно только во вложении, использовать поддерживаемую инструментом передачу изображений из разговора; не подменять визуальный референс текстовым описанием. Если инструмент не может принять все изображения, сообщить ограничение.
- Скопировать фактически использованные фотографию и стилевые референсы в `input/<poster-id>/` нового запроса; записать относительные пути и SHA-256 в манифест, точный промпт — в `prompt/`. Указать роли изображений в метаданных.
- Сохранить новый PNG в общем `output/`, обновить README запроса и галерею. Не искать новые референсы и не делать типографические подложки без необходимости.
